# Contributing to Game Collections

Thanks for helping. There are three ways to contribute: translating, reporting problems, and changing the code.

## Translating

Translations are managed on [Crowdin](https://crowdin.com/project/game-collections). Join the project, pick your
language and translate there; no coding or GitHub account is needed. New translations are added to the extension in
its next release, and any string that isn't translated yet is shown in English.

- **Don't edit the translation files in this repository** (anything in `source/GameCollections/Localization/` other
  than `en_US.xaml`). They're generated by Crowdin and overwritten on every sync, so pull requests that change them
  can't be merged.
- To request a language that isn't on Crowdin yet, [open an issue](https://github.com/X4Lo/GameCollections/issues).
- If an English string is unclear or wrong, comment on it in Crowdin or open an issue.

## Reporting a bug or requesting a feature

[Open an issue](https://github.com/X4Lo/GameCollections/issues). For bugs, the form asks for the extension and
Playnite versions, and what you did, what you expected and what happened instead. Mention the theme you use too,
since many display problems depend on it.

Playnite's log (`extensions.log` in Playnite's folder, or `%AppData%\Playnite` for an installed copy) usually shows
the cause, so attach it if you can. Check the open issues first, in case it has already been reported.

## Changing the code

Before starting on anything large, open an issue to discuss it, so your work fits where the extension is going.

### Setting up

You need Windows, the .NET SDK and a Playnite 10 installation to try your changes. Build with:

```
dotnet build source/GameCollections.sln -c Release
```

The `.pext` package is written to `dist/`; open it to install your build in Playnite. See
[Architecture and development](docs/architecture.md) for the repository layout and the
[Developer guide](docs/developer-guide.md) for how everything works.

### Rules to follow

- **Target what Playnite runs:** .NET Framework 4.6.2 and C# 7.3. Don't add NuGet packages that Playnite doesn't
  already ship without discussing it first.
- **Match the surrounding code:** its naming, comment style and MVVM structure.
- **No user-visible text in code or XAML.** Add a `LOCGameCollections_*` key to
  `source/GameCollections/Localization/en_US.xaml` only, and read it with `Loc` in code or `DynamicResource` in XAML.
  Crowdin picks up new and changed strings automatically.
- **Use theme resources** (`DynamicResource` brushes, fonts and styles) rather than fixed colours, so light and dark
  themes both work.
- **Changing the data file:** if a change to `collections.json` means existing data has to be converted, bump
  `SchemaVersion` and add a migration step, as described in the developer guide. Adding a field with a safe default
  doesn't need one.
- **The build must have no warnings.**

### Testing

There's no automated test project yet. Test your change by hand in Playnite, in a light and a dark theme, and go
through the checklist in the [Developer guide](docs/developer-guide.md#testing) for the areas you touched.

### Pull requests

- Keep each pull request to one change, and describe what it does and how you tested it. Screenshots help for
  anything visible.
- Write commit messages in the [Conventional Commits](https://www.conventionalcommits.org) style used in this
  repository, such as `feat: add card size slider` or `fix: search box height on collection page`.
- Don't change the version number, `CHANGELOG.md` or `manifests/installer_manifest.yaml`; they're updated when a
  release is made.
